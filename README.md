# Микросервисы: подходы  
  
## Задача 1: Обеспечить разработку  
Для процесса разработки предлагаю  GitLab в качестве облачной системы контроля версий и непрерывной интеграции/поставки (CI/CD)  
  
Основные характеристики выбранного решения:  
1. может быть использован как облачное решение или развернут на собственных серверах (self-hosted)  
2. поддерживает систему контроля версий Git и позволяет создавать отдельные репозитории для каждого микросервиса  
3. интегрированная система CI/CD в GitLab позволяет автоматизировать процесс сборки, тестирования и развертывания приложений; поддерживает запуск сборок по событиям из системы контроля версий или по кнопке с указанием параметров через интерфейс проекта  
4. возможность привязывать настройки к каждой сборке через конфигурационные файлы .gitlab-ci.yml; создание шаблонов для различных конфигураций сборок с помощью директивы include  
5. возможность безопасного хранения паролей и ключей доступа через переменные окружения в проекте  
6. поддерживает возможность иметь несколько конфигурационных файлов .gitlab-ci.yml или использовать один файл с несколькими задачами (jobs) для разных сред  
7. кастомные шаги могут быть добавлены через скрипты внутри задач (jobs) в пайплайне CI/CD  
8. поддерживает использование собственных Docker-образов как окружений для выполнения задач CI/CD  
9. возможность развернуть агенты GitLab Runner на своих серверах под управлением Linux, macOS, Windows или Docker/Kubernetes кластере  
10. параллельный запуск нескольких задач (jobs) внутри пайплайна возможен благодаря использованию нескольких экземпляров раннеров (runner)  
  
  
## Задача 2: Логи  
Для обеспечения сбора и анализа логов в микросервисной архитектуре предлагаю решение на основе стека ELK (Elasticsearch, Logstash, Kibana)  
  
Выбранное решение удовлетворяет требованиям:  
1. Logstash собирает логи со всех хостов, обслуживающих систему. Он может собирать логи из различных источников, включая stdout приложений. Filebeat может использоваться для сбора логов напрямую с серверов и отправки их в Logstash для дальнейшей обработки  
2. Приложения могут просто выводить логи в stdout без дополнительных изменений  
3. Для гарантированной доставки логов можно использовать механизмы повторной отправки и буферизации в Logstash  
4. Elasticsearch индексирует собранные логи, что позволяет быстро искать и фильтровать записи по различным критериям  
5. Kibana предоставляет удобный интерфейс для разработчиков для поиска по записям логов и создания пользовательских дэшбордов  
6. В Kibana можно сохранять ссылки на конкретные запросы или дэшборды, что позволяет легко делиться результатами с другими членами команды  
  
Стек ELK является широко распространенным решением для централизованного ведения журналов благодаря своей гибкости и масштабируемости. Все компоненты ELK являются открытыми программными продуктами, что снижает затраты на лицензии. Кроме того, стек ELK легко интегрируется с другими инструментами DevOps-процесса (например, Docker), что упрощает его использование в микросервисной архитектуре  
  
  
## Задача 3: Мониторинг  
Для обеспечения сбора и анализа состояния хостов и сервисов в микросервисной архитектуре предлагаю решение на основе стека Prometheus, Grafana и Docker  
  
Выбранное решение удовлетворяет требованиям:  
1. Prometheus собирает метрики со всех хостов, обслуживающих систему  
2. Prometheus может собирать данные о системных ресурсах  с помощью экспортеров: Node Exporter для CPU, RAM и HDD; Netstat Exporter или другие плагины для мониторинга сетевых подключений  
3. Для каждого сервиса можно использовать специфичные экспортеры или интегрировать Prometheus напрямую в приложение через библиотеки  
4. Каждый микросервис может предоставлять свои собственные метрики через HTTP API  
5. Grafana предоставляет удобный интерфейс для создания дэшбордов на основе данных из Prometheus  
  
Этот стек является широко распространенным решением. Prometheus обеспечивает эффективный сбор различных типов метрик из разных источников. Grafana позволяет создавать гибкие панели мониторинга на основе собранных данных. Этот подход легко интегрируется с контейнерными технологиями Docker, для его использования в микросервисной архитектуре
